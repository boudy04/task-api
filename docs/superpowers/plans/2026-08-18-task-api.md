# Task API Implementation Plan

> Spec: `docs/superpowers/specs/2026-08-18-task-api-design.md`
> Project: `p3/` — FastAPI task-tracker CRUD API with Postgres, token auth,
> Docker, CI, Railway deploy. Fed by a Kotlin app in Week 6–7.

## Overview

Build and ship a public CRUD REST API (FastAPI + Postgres + SQLAlchemy).
Each task ends with a runnable test cycle (pytest) against a real Postgres.
Order: environment first (a reachable local Postgres is a hard prerequisite),
then scaffold, then data layer, then endpoints, then packaging/deploy.

## Global constraints

- Python 3.11 via **uv** (available on this machine). No pip in uv venvs — use
  `uv add` / `uv run`.
- **No Docker/WSL2 possible on this machine**: it runs a custom "X-Lite"
  debloated Windows build with the VirtualMachinePlatform payload removed and
  no repair source, so WSL2 cannot boot a distro and Docker Desktop is a dead
  end (verified, user ruled Option A). Local Postgres = **native EDB install
  as a Windows service** (service account sidesteps the admin block). The
  Dockerfile + docker-compose still ship and are verified via CI + Railway.
- Local account is Windows admin; Postgres refuses to run as admin directly —
  the service account handles this.
- Git identity: `boudy04 <boudy04@users.noreply.github.com>`.
- GitHub push pattern (from prior projects): embed PAT in remote URL, push,
  then `git remote set-url origin https://github.com/boudy04/<repo>.git`.
  git-stats PAT works only for git-stats; task-api may need its own or the
  classic PAT from `~/.git-credentials`.

## Dependencies

- `fastapi`, `uvicorn[standard]`, `sqlalchemy`, `psycopg[binary]`,

## Tasks

### 1. Install native Postgres 16 (env gate)

**Summary:** Install Postgres 16 via the EDB Windows installer as a Windows
service (port 5432, superuser `postgres`), verify `psql` connects. This is the
replacement for a local Docker container — the machine cannot run WSL2/Docker
(X-Lite build), so local Postgres comes from the native service.

**Files:** none (system install)

**Test cycle:**
1. Download + silently install `postgresql-16.9-1-windows-x64.exe`
2. `Get-Service postgresql*` shows `Running`
3. `psql -U postgres -h localhost -p 5432 -c "SELECT version()"` succeeds
   (password from install)
4. Create database `taskapi` for dev + `taskapi_test` for tests

**Duration:** ~30 min download + install

**Gate:** `psql` round-trip against the local service. **If the installer fails
or the service won't start, stop and return to the user** — a reachable local
Postgres is a hard dependency of every later task.

---

### 2. Scaffold project + config

**Summary:** Create `pyproject.toml` (uv), app package skeleton, and
`app/config.py` (pydantic-settings) reading `DATABASE_URL` + `AUTH_TOKEN` with
sane defaults.

**Files:** `pyproject.toml`, `.gitignore`, `app/__init__.py`, `app/config.py`

**Test cycle:** `tests/test_config.py` — assert defaults when env vars unset
(`AUTH_TOKEN` non-empty default, `DATABASE_URL` points at
`postgresql+psycopg://...localhost:5432/taskapi`), and env override works.

**Duration:** 15 min

**Gate:** `uv run pytest` green.

---

### 3. Postgres test DB + test fixtures

**Summary:** Ensure the `taskapi_test` DB exists (created in Task 1), add
`tests/conftest.py` (engine from config pointing at local Postgres, create
schema once per session, truncate `tasks` between tests), and a
`tests/test_db.py` smoke test proving a real query round-trips.

**Files:** `tests/conftest.py`, `tests/test_db.py`

**Test cycle:**
1. (Task 1 already) local Postgres service running, `taskapi_test` exists
2. `tests/test_db.py` — `SELECT 1` via SQLAlchemy engine succeeds, table
   create/drop round-trip works
3. `uv run pytest` green

**Duration:** 20 min

**Gate:** `tests/test_db.py` passes against the native local Postgres.

---

### 4. Models + schemas (data contracts)

**Summary:** Add `app/models.py` (SQLAlchemy `Task`: id, title, description,
status, priority, created_at, updated_at, per spec table) and `app/schemas.py`
(pydantic `TaskCreate` — title required, status/priority validated enums with
defaults; `TaskUpdate` — all optional; `TaskRead` with id + timestamps).

**Files:** `app/models.py`, `app/schemas.py`, `tests/test_schemas.py`

**Test cycle:** `tests/test_schemas.py` — valid TaskCreate accepted; missing
title → 422; invalid status/priority → 422; defaults applied; TaskUpdate
accepts empty subset.

**Duration:** 20 min

**Gate:** `uv run pytest` green.

---

### 5. db session + auth dependency

**Summary:** Add `app/db.py` (engine, `SessionLocal`, `Base`,
`get_db` dependency) and `app/auth.py` (`get_current_token` dependency: reads
`Authorization: Bearer <token>`, compares to `AUTH_TOKEN`, 401 JSON on
missing/mismatch).

**Files:** `app/db.py`, `app/auth.py`, `tests/test_auth.py`

**Test cycle:** `tests/test_auth.py` — need a minimal FastAPI app wired with the
dependency. 401 for missing header, 401 for wrong token, 200 for valid token.
(Test app lives in the test file; real wiring comes in Task 7.)

**Duration:** 20 min

**Gate:** `uv run pytest` green.

---

### 6. Tasks router (all CRUD)

**Summary:** Add `app/routers/tasks.py` implementing all six endpoints per
spec: GET list (with `?status=` filter, newest first), POST create (201),
GET by id, PUT full update, PATCH partial, DELETE (204); 404 JSON
`{"detail": "Task not found"}` for unknown ids.

**Files:** `app/routers/tasks.py`, `tests/test_tasks.py`

**Test cycle:** `tests/test_tasks.py` against real PG —
1. POST → 201, body echoes id + defaults
2. GET list → newest first; `?status=done` filters
3. GET unknown id → 404 JSON
4. PUT replaces fields; PUT unknown id → 404
5. PATCH `{"status": "done"}` changes only status
6. DELETE → 204; second DELETE → 404
7. Invalid body → 422

**Duration:** 40 min

**Gate:** `uv run pytest` green (full suite).

---
